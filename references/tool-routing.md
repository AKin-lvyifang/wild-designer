# 按需工具与可编辑交付

先根据用户需要完成方案，再选择表达它的工具。本文件只用于视觉生成、HTML 原型、原生设计稿或画布交付；不是独立设计讨论的前置流程，也不声明任何宿主已安装或端到端可用。

## 交付先于工具探测

- 方案/布局咨询：在对话或已有设计文档里完成推荐、结构和取舍，不探测无关 MCP，不为了走流程生图。
- HTML/CSS 原型：已有本地文件与浏览器能力足够时直接使用；在本任务允许的目录写入并预览，不依赖 Cowart/Paper/Figma。只做设计原型不等于获准修改正式产品或部署。
- 位图视觉稿：优先宿主内置生图；编辑前查看所有输入，生成后看实际返回结果，不为工具验证消耗额度。
- 原生可编辑稿：目标与能力明确时，在适合的 Paper/Figma 或其他编辑器重建布局、文字与简单矢量；复杂照片/插画可以保留位图，说明边界。
- 画布比较：仅当用户需要或本任务已使用可用画布时，插入产物并维护来源。画布缺失不妨碍方案、图片、HTML 或其他设计稿交付。

已有合适视觉稿不重复生成。用户明确只要图片时不额外创建云端设计文件；多个编辑器可用时只选用户指定或本任务已关联的一个，条件相同且无指定时可优先 Paper。

## 最小能力核实

1. 按当前交付发现真实工具名、schema 和输入输出能力，复用本轮有效结果。应用打开、历史安装、出现工具名都不足以证明相关操作可用。
2. 对要使用的可选编辑器/画布做一次最小只读调用，确认目标与相关能力；账号读取成功不代表某个文件可写。只读本次需要的范围，不输出账号邮箱、密钥或私人文件清单。
3. 确认新布局、文字、简单矢量、图片放置、读回、截图/导出中本次需要的能力及获授权范围。明确拒绝、要求额外连接或权限时停止该路径，不改账号/MCP配置、安装程序或换接口绕过。
4. 同一次操作已有证据就复用；目标改变或失败后按需更新。单个可选路径失败后先交付可完成部分，只有明确可修复且仍获授权的原因才重试。

## 选择模型与取回文件

使用工具实际支持的默认模型；用户明确指定型号，且当前 schema 同时支持型号字段和该值时才填写。不要从产品宣传或模型记忆猜字段、伪造型号。无法指定时直接说明用默认能力并继续，只有工具回执能证明时才报告具体型号。

文件路径来自本次工具明确返回的文件、附件、受支持下载接口或本任务实际创建的文件。不得读 session JSONL、聊天日志或旧 generated_images 目录找结果。不支持取回本地文件时可交付工具已展示的图片，说明尚未入画布，不编造路径。

## 各宿主的适配边界

**Cowart**：需要真实的原生图片插入、状态读取/保存、读回与预览能力。使用 [cowart-workflow.md](cowart-workflow.md) 和 [canvas-state.md](canvas-state.md)；位图画布不是可编辑 UI 重建器。widget/HTML资源可读，不证明实际画面已在宿主显示。

**Figma**：按当前可用 Figma Skill 与工具文档操作，只在新文件或获授权页面空白区创建所属内容。返回并读回真实 file/page/node ID。导入栅格图不会得到原生文字或原始路径；没有相应 metadata API 时用任务外部记录关联，不虚构隐藏字段。多目标归属不清时先交付独立成果，只有明确要求写入该编辑器且无法确定目标时才问一个问题。

**Paper**：当前工具必须确实支持本次需要的文档读取、布局/文字/素材创建和读回。支持的 HTML/CSS/SVG 以当前接口为准，不把桌面粘贴能力等同于 MCP 能力，不猜历史函数或端点。工具缺失时保持独立交付，不自动配置连接。

**其他画布/编辑器**：只有明确的真实接口映射、目标归属、原生写入、来源记录和读回合同才适配。不能把名字带 canvas 当成集成完成，不能把 Cowart 的 shape/meta/snapshot 字段套给其他宿主。

## 从图像参考到可编辑稿

1. 沿 brief、同一 styleContract、原始文字和交互合同拆成布局、文字、简单图形与图片区域；不在重建时重新选风格。已知文案优先于 OCR 猜测。
2. 在新容器建立对齐、间距、约束/自动布局；创建原生文字与简单矢量。照片、纹理、复杂插画作为独立位图。不要逐字描边替代文字，也不把整图放进 SVG 包装后称矢量稿。
3. 无法分离的部分用已有授权素材或支持的流程重建；做不到就标明位图区域，避免叠字重影。不承诺恢复隐藏图层或无损拆图。
4. 验证结构：真实节点类型、内容、边界和容器关系；部分可编辑就如实说明部分。验证视觉：实际截图/导出中的层级、比例、间距、字体、裁切、缺失与代表性长文案换行，简述字体替代或效果简化。
5. 高保真还原发生偏差时先查容器尺寸，再查字体/换行、间距，最后查素材裁切与装饰。像素差只帮助定位，不能换算成设计质量或交互正确率。
6. 保留源图与父版本。可编辑稿是同一候选的另一种表示，关联真实宿主 ID，不因转换完成改变采用状态；无 Cowart 时仍在当前设计记录中维护这些关系。

可编辑结构和视觉一致分别验证。没有截图就只报告结构证据；静态图不能证明过渡/交互，按 [interaction-motion.md](interaction-motion.md) 在真实可运行环境检查相关状态。

## 预览、失败与完成

优先复用本任务已打开的预览；只有宿主确实支持才说打开在指定位置。正常图、编辑器原生稿、画布预览分别报告。可选工具不可用不影响完整方案；只在用户明确要求的特定交付无法完成时报告剩余缺口。

不覆盖无关作品、不改凭据或账号、不上传未授权私人素材。只有当前任务另有发布授权时才发布。先核对回执与读回，再说文件已写入或版本已采用。

## 可选路径规划 helper

`scripts/route_design.py` 是纯输入/输出工具，适用于位图与原生编辑器适配；独立方案和 HTML 原型无需调用。其 `brief_only` 表示没有进入这些创作工具，不限制方案应包含的结构与设计判断。它不会发现工具、查参考库、看图或生成设计。

```sh
python3 <skill目录>/scripts/route_design.py <本轮能力证据.json>
```

调用者只能填写已核实的能力：`image.available/tool`，各 adapter 的 `adapterKnown/targetResolved/scopeAuthorized/tools/probe`；示例测试里的 true 不是实际证据。模型偏好使用 `image.preferredModel`，且须匹配 `modelSelector/supportedModels`。缺少明确偏好时用默认模型。

`style` 可带已有 `existingContract/projectSpec`、当前明确 `userChanges`、`explicitStyle/matchedBrandReference`、可用 `helpers`。只在有具体资料缺口时填 `referenceNeed`；没有缺口就不安排库检索。输出是建议路径和约束合并，不是用户已选方案或工具已执行。
