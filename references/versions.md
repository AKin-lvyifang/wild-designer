# 候选、版本与采用

多稿、跨轮或跨页面交付时使用。单次咨询在对话里记录目标、候选和用户反应即可，不强制创建 JSON、UUID 或画布。没写文件就不说已保存。

## 候选与采用状态

- 区分项目、目标和候选；首页、详情页各有自己的主稿。每个候选保存来源、父版本、参考、风格版本和设计理由；保留原稿和历史稿，不覆盖、删除或隐藏无关作品。
- 新候选是 `proposed`。用户明确选择，或明确委托助手定案后，记录真实选择/委托原话及理由，才设为 `adopted`；旧主稿转 `superseded` 并保留。
- 生成成功、当前选中、风格选定、助手推荐或可编辑转换，都不等于采用。
- 对比页里的点击只有经可靠回传并完成记录更新后才算采用；没有回传时以聊天中的选择为准。

## 记录位置

- 多稿或跨轮交付沿用已有任务文档或输出文件保存目标、候选、基底、用户反应、推荐/采用和改动理由。
- 用户在引导中确认的偏好（如“留白优先”“不要冷色”）写进 `styleContract`，并注明来自用户的哪次反应。
- 使用 Cowart 时，可变状态只放本技能的文字记录，图片来源不变。保存细节见 [canvas-state.md](canvas-state.md) 和 [cowart-workflow.md](cowart-workflow.md)：先读 snapshot/revision、保留无关记录、传 expectedRevision；冲突时重读重算，最多两次；核对 skippedRecords 和读回后再报告成功。其他宿主按其真实接口，不套用 tldraw 字段。

## 文件路径

文件路径只能来自工具明确返回的文件/附件、支持的下载接口或本任务实际创建的文件。不要从 session JSONL、聊天日志或旧生图目录猜路径。编辑前看输入，生成后看结果，不为验证安装消耗生图额度。

## 许可与发布

画布和第三方组件的许可证各自适用。公开发布需要用户另行授权。
