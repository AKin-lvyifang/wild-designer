# 从模糊想法形成设计方案

本文件指导方向探索、参考借鉴和视觉改稿。用户没有想法、不会布局或说不清喜欢什么时，也能直接开始；不要求他先准备风格词、参考图或完整需求文档。它可以独立完成设计方案，不以产品开发、可编辑设计软件或画布为前提。

复用当前对话、已有内容、用户偏好和项目规范。能推断的就提出合理假设并推进；只有答案会改变主要目标或成果时，才问一个简短问题。当前明确需求优先于已批准项目规范，项目规范优先于外部参考建议。

## 1. 从目标找到画面的主张

先用一两句话确定：谁在什么场合看它，最需要理解或完成什么，以及必须保留什么。已有 brief 足够时直接复用，不另填一张表。

再把目标落成一句能指导设计取舍的**视觉命题**：希望第一眼注意什么，用哪种具体关系做到，为什么适合这次任务。

例如，“让店主一眼找出需要处理的订单”可以推出“待处理列表占主要面积，异常标记靠近订单，操作紧跟对象”；“让人感到这是安静的阅读空间”可以推出“正文先进入视线，短行宽与清楚的标题层级组织阅读，工具退到边缘”。不先抽一个风格，再给产品套上它的配色和卡片。

“高级、温暖、有冲击力”等词可以保留为用户原话，但要翻译成可见选择：标题和正文相差多少、图像占多大面积、内容多密、色彩对比多强、边缘与材质怎样处理。只确定本轮需要的关系，不在探索前锁死所有坐标和数值。

## 2. 把主张落到结构与层级

先安排读者的注意顺序或使用者的操作顺序，再选组件和装饰。用几句结构说明、简单方框或小样表达即可，不强制制作独立线框文档。

| 媒介或任务 | 先决定什么 |
| --- | --- |
| 工具、后台、内容浏览 | 当前对象、关键判断与主要动作放在哪里；第一屏能否开始做事 |
| 官网、发布页、介绍页 | 核心主张如何由真实产品或证据支持；读者随后需要知道什么 |
| 封面、海报 | 标题、主体和必要信息谁先谁后；小尺寸下能否识别主题 |
| PPT 配图、解释图 | 这张图要支撑哪个论点，哪些关系必须直接看出来 |
| 风格板 | 哪些字体、颜色、图像处理和比例共同表达同一个方向 |

结构从内容关系推出：连续处理用稳定列表，横向比较才并列，图像负责解释或情绪时给它相应分量。网格、卡片、左右分栏都可以用，但应说得出它们对当前任务的好处。不要为了显得特别而改变用户已熟悉的主要操作，也不要让所有区块拥有相同分量。

## 3. 参考要解释因果，资料库只补缺口

先说明参考的用途：借视觉关系、沿用现有品牌、保留固定区域，还是准确还原。实际看过图片后再描述画面；只有文字资料时，明确它是文字参考。

借鉴时用一条短链表达：**看见的特征 → 它起的作用 → 本任务是否需要 → 具体借用或舍弃什么**。

例如，“参考把图片放得很大，让人先感到空间氛围；我们的页面更需要比较价格，所以保留它的字体比例，缩小图片，把方案差异放在同一视线里”。保留品牌与业务内容，不把参考里的营销模块、人物、商标或数据顺手搬来。参考里没有的装饰也不默认补上。

优先使用相关的已有素材和当前项目规范。只有缺少某种设计依据时，才搜索公开案例或查询可用风格资料；不把竞品调研设成每个任务的必经步骤。

`ui-ux-pro-max` 可按需补充风格、颜色或字体候选，`design-md` 可按需把明确的品牌气质细化为规则。使用前从宿主技能发现结果定位当前安装入口，只读取与缺口有关的内容；不依赖固定路径、版本、图库数量或特定命令。它们缺失时照常用已知设计原则和本轮内容完成方案，不自动安装，也不假称查询成功。外部建议不能变成第二套项目规范或替换既有技术栈。

## 4. 做两个有实质差异的方向

方向尚未明确时，默认给两个候选；已有明确方向、用户只要一版或本次只是局部修正时，直接沿该方向推进。不为了凑数额外出图，也不把探索拆成固定的多轮审批。

每个候选简短交代：

- 主要视觉命题和对应的结构；
- 几个可以在画面里指出来的特征；
- 为什么适合本任务，以及付出的代价。

候选共享目标、关键内容、主要动作和展示尺度，差异来自阅读顺序、比例、信息组织或图像用途等有意义的选择。已锁定的品牌和交互继续共用；不要为了区别候选而改掉这些约束。

制作前后各看一次：遮住名称与说明，两个方案还能凭主要区域的安排分辨吗？如果只是换背景明暗、强调色或圆角，它们通常是同一方向的变体。调整其中一个的结构或表达重点；用户本来就在比较配色或局部变体时，则按该范围比较，不强求换布局。

先做能暴露方向优缺点的代表性小样。复杂表单要展示真实表单密度，工具要展示关键工作区，不能只画一张漂亮封面替它证明设计可用。使用相同的关键文案和数据，不让某个方案靠删掉难处理的内容显得更好。

用户要求设计且上下文足够时，直接完成本轮所需的小量候选。按真实工具能力展示图片或可编辑小样，已有参考与新生成示例分别标明。没有生成或预览能力时，可用具体结构、色板和设计说明形成方案，说明哪些效果尚未看到；不编造图片，也不将工具缺失变成反复提问。

推荐应依据目标适配、内容承载、识别度、可读性和制作代价。没有必要让用户回答专业术语；他可以指出喜欢的区域、想保留的感受或无法接受的地方。用户未选择也未委托助手定案时保持候选状态；制作成功或助手推荐本身不等于用户选择。

## 5. 把反馈变成下一步设计决定

收到“太普通”“太挤”“再高级一点”时，先对照实际画面和原目标定位问题。能从画面判断的直接解释并修改；有两种会导致不同结果的合理理解时，才用一个具体对比帮助用户澄清。

| 反馈 | 先检查的证据 | 可能的调整 |
| --- | --- | --- |
| 太普通、没有特点 | 主张是否能从构图读出来，候选是否沿用同一模板 | 重新安排焦点、比例或图像用途，不先加纹理和发光 |
| 太挤、看不清 | 主次是否混在一起，是真实内容太多还是容器过窄 | 调整信息优先级、分组、阅读宽度或滚动范围，不把所有字缩小 |
| 太花、用起来累 | 有多少元素同时争抢注意，装饰是否影响阅读和操作 | 减少无关竞争，保留能表达主题的一两处重点 |
| 不像我要的感觉 | 用户原话与可见选择是否一致，参考是否借错了关系 | 修改具体字体、比例、对比或图像处理，并说明预期变化 |

以上是诊断起点，不是看到关键词就执行的固定处方。每轮先确定一个最影响目标的问题，说明要保留的部分和本轮改变的关键变量；可以一起修改同一原因造成的多个细节，不机械拆成多轮。

修改后看新旧实际结果，说明问题改善了什么、代价是什么、有没有丢掉原有特色。内容完整与视觉表现分别检查；不要把“更整齐”直接当作“更好”，也不要把个人偏好说成客观缺陷。

连续修改仍无明显收益时，回查目标假设、参考是否真正传入、结构是否过早固定、内容是否放不下，以及生成能力是否存在限制。先调整解释或方案，不重复追加同样的装饰和形容词；不以固定轮数或审美评分代替判断。

## 6. 在实际使用尺度检查

查看真实产物，而不仅是缩略图或工具成功提示。至少核对本轮相关的内容准确性、第一眼焦点、阅读顺序、重复规则和必须保留的约束。

UI 要区分逻辑视口、文档高度和图片像素。例如宽 1024 像素的手机设计图，可以表达宽 390 的手机布局，不能据此把按钮和文字按桌面尺度评价。按目标显示大小检查主要文字、控件和信息密度；长文本、更多数据与相关状态要有处理方案。只有真实页面或原生设计中的操作才能证明交互，图片只能证明看到的状态。

封面检查小缩略图中的主题识别和目标尺寸下的细字；PPT 检查预计观看距离下的论点与标注；完整长页同时看整页节奏和局部文字，不能用一张首屏代表全页。已有有效证据可复用，只补本次变化相关的检查。

没有足够画面或运行能力时，明确区分“方案已确定”“视觉待查看”“交互未验证”，不让概念讨论承担它无法证明的验收。

## 7. 用一个 styleContract 维持方向

已有批准的项目设计规范时，沿用其路径和版本，只记录本次选择与必要补充。没有真源时，把本轮选定的规则记为与任务规模相称的 `styleContract`；它是后续页面和修改共同遵循的设计记录，不需要另起完整设计系统。

需要持久化或跨页引用时记录 `styleId`、`revision`、名称、来源和 `proposed/adopted` 状态；单次对话可用简短名称与文字规则。内容按需包含：

- 目标与视觉命题，以及结构、焦点和阅读顺序；
- 颜色的用途、字体与替代、字号层级、密度和间距关系；
- 适用的组件、反馈与内容过渡规则，或图片类任务的构图与图像处理；
- 品牌与内容约束、明确不借用的特征、允许变化的部分；
- 本轮接受的取舍与尚待验证的假设。

提出的色值、尺寸或字体是设计选择；未经测量时不要冒称来自参考图的精确数值。两个候选各有自己的标识，明确风格选择与具体图片采用是两个决定。用户已明确指定的方向可直接沿用；未获明确选择或委托定案时，助手自行提出的候选仍为备选。明确委托时记录委托原话、选定方案与理由，再按主入口继续推进。

没有画布时，小任务可以在对话中用一段“已选方向与规则”记录；需要跨轮、跨页面或交接时，保存到当前任务产物或项目已有设计记录，并引用同一份来源。有画布或设计编辑器时，只关联真实文件、页面或节点，不复制一份互相竞争的规则，也不依赖不存在的隐藏元数据。实际写入成功后才称已保存。

后续小样、生图、可编辑重建和页面延展都沿用同一版本。根据内容调整版式，不重新随机挑字体、配色和圆角。用户改变方向时更新合同版本，保留旧候选和来源；新要求若与现有规则冲突，先说明影响，能依上下文判断就继续，不能判断才问一个必要问题。
